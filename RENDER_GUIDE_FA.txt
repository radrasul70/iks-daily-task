راهنمای انتشار نسخه نمایشی سامانه دیلی‌تسک روی Render
====================================================

این بسته برای ارزیابی مدیریتی است و جایگزین استقرار نهایی روی VM شرکت نیست.

پیش‌نیازها
----------
1) یک حساب Render
2) یک حساب GitHub
3) ساخت یک مخزن خصوصی (Private Repository) در GitHub

انتقال فایل‌ها به GitHub
-----------------------
1) ZIP را روی رایانه استخراج کنید.
2) محتویات پوشه ImenKhodroShargh_DailyTask_v18 را در مخزن خصوصی GitHub بارگذاری کنید.
3) مطمئن شوید render.yaml، app.py، index.html و requirements.txt در ریشه مخزن باشند.
4) فایل پایگاه داده، نسخه پشتیبان، رمزها و اطلاعات واقعی شرکت را در مخزن بارگذاری نکنید.

ساخت سرویس در Render
--------------------
1) در Render گزینه New و سپس Blueprint را انتخاب کنید.
2) حساب GitHub را متصل و مخزن خصوصی را انتخاب کنید.
3) Blueprint را بررسی و ایجاد کنید.
4) در زمان درخواست متغیر INITIAL_ADMIN_PASSWORD یک رمز منحصربه‌فرد حداقل ۱۲ نویسه‌ای تعیین کنید.
5) پس از Deploy موفق، آدرس onrender.com سرویس را باز کنید.
6) نام کاربری اولیه: admin
   رمز عبور: همان مقداری که برای INITIAL_ADMIN_PASSWORD وارد کرده‌اید.
7) پس از ورود، رمز را در صورت امکان از بخش مدیریت/تنظیمات حساب تغییر دهید.

نکات حیاتی
----------
- render.yaml یک دیسک پایدار یک گیگابایتی تعریف می‌کند؛ دیسک پایدار در Render
  نیازمند سرویس پولی است. بدون آن، فایل‌های پایگاه داده ممکن است با Deploy یا
  راه‌اندازی مجدد از بین بروند.
- پایگاه داده و پشتیبان‌ها در /var/data ذخیره می‌شوند.
- این نسخه برای داده‌های آزمایشی و غیرمحرمانه است. تا تأیید امنیتی IT، اطلاعات
  واقعی کارکنان، مکاتبات یا داده‌های محرمانه شرکت را وارد نکنید.
- نشست‌های ورود در حافظه سرویس نگهداری می‌شوند؛ پس از Restart/Deploy ممکن است
  کاربران نیاز به ورود مجدد داشته باشند.
- برای استقرار نهایی سازمانی، IT باید احراز هویت، سیاست رمز، ثبت رخدادها،
  پشتیبان‌گیری، شبکه، HTTPS و پایگاه داده را بازبینی و تأیید کند.
- برای بازبینی کد و انتشارهای بعدی، مخزن GitHub را خصوصی نگه دارید و دسترسی‌ها
  را فقط به افراد مجاز بدهید.
